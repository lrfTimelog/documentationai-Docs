Returns the account's customer statuses with their group flags, default and active flags.

| | |
|---|---|
| API | Reporting API (short lists) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetCustomerStatusShortList` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

No filters: inactive statuses and the system status for multi-customer projects are included. CustomerStatusType tells customers, suppliers and leads apart.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

import requests

               xmlns:tlp="http://www.timelog.com/ws/tlp/v4_4">
  <soap:Body>
    <tlp:GetCustomerStatusShortList>

    URL,
    data=envelope.encode("utf-8"),

## Response

The result is an XML document inside `GetCustomerStatusShortListResult`: a `tlp:CustomerStatuses` root with one `tlp:CustomerStatus` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: Status name ascending.

<ResponseField name="tlp:CustomerStatus" field-type="CustomerStatusShort[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="CustomerStatus fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Customer status ID.**
</ResponseField>

<ResponseField name="Name" field-type="string">
**Name.** Not cleaned of XML-forbidden characters.
</ResponseField>

<ResponseField name="CustomerStatusType" field-type="integer">
**Status groups.** 3 = customer + supplier).
</ResponseField>

<ResponseField name="IsDefault" field-type="integer">
**Default status.** The XSD declares it required boolean.
</ResponseField>

<ResponseField name="IsActive" field-type="integer">
**Active.** No filter - inactive statuses are listed. The XSD declares it required boolean.
</ResponseField>

</Expandable>
</ResponseField>
