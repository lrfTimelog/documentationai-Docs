Returns the account's tasks with id, name, project, active flag and hierarchy.

| | |
|---|---|
| API | Reporting API (short lists) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetTasksShortList` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

Filters: project, active status, task type. Tasks of project templates ARE included - unlike GetTasksRaw; filter on ProjectID against GetProjectsShortList. ParentID is omitted when NULL.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="projectID" field-type="integer" required="true">
0 = no filter. A project-template id is accepted and returns the template's tasks.
</ResponseField>

<ResponseField name="status" field-type="integer" required="true">
Use `-1` for no filter. NOTE: GetProjectsShortList's 'all' is -2; -1 there returns nothing.
</ResponseField>

<ResponseField name="taskTypeID" field-type="integer" required="true">
Task type. 0 = no filter.
</ResponseField>

## Response

The result is an XML document inside `GetTasksShortListResult`: a `tlp:Tasks` root with one `tlp:Task` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: Project ID, then task sort order, then task name, ascending.

<ResponseField name="tlp:Task" field-type="TaskShort[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="Task fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Task ID.**
</ResponseField>

<ResponseField name="Name" field-type="string">
**Task name.** Raw value: not cleaned of XML-forbidden characters.
</ResponseField>

<ResponseField name="ProjectID" field-type="integer">
**Project ID.** Project of the task. May be a project template.
</ResponseField>

<ResponseField name="Status" field-type="integer">
**Active status.** The status parameter filters on it.
</ResponseField>

<ResponseField name="ParentID" field-type="integer">
**Parent task ID.** Treat 'absent' and 0 alike as 'top-level task'.
</ResponseField>

<ResponseField name="IsParent" field-type="integer">
**Is parent.**
</ResponseField>

</Expandable>
</ResponseField>
