---
title: "GetExpensesRaw"
description: "Reporting API: Returns the account's project expenses in a purchase-date range, with amounts, VAT, supplier, payment method and approval / payment / invoicing flags."
---

| | |
|---|---|
| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetExpensesRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

Receipts are NOT returned. 9999-12-31).

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="customerID" field-type="integer" required="true">
Customer of the expense's PROJECT. 0 = no filter.
</ResponseField>

<ResponseField name="projectID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="supplierCustomerID" field-type="integer" required="true">
Supplier. 0 = no filter.
</ResponseField>

<ResponseField name="employeeID" field-type="integer" required="true">
Employee who registered the expense. 0 = no filter.
</ResponseField>

<ResponseField name="employeeDepartmentID" field-type="integer" required="true">
Department of the employee's CURRENT user profile, INCLUDING its sub-departments: matches when the given ID is in the department's ancestor path. The department at the time of the expense is not considered. 0 = no filter.
</ResponseField>

<ResponseField name="expenseTypeID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="paymentMethodID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="startDate" field-type="dateTime" required="true">
Purchase date >= value. ALWAYS applied - there is no 'no limit' value. An invalid value -> ASMX fault.
</ResponseField>

<ResponseField name="endDate" field-type="dateTime" required="true">
Purchase date &lt;= value. Same rules as startDate.
</ResponseField>

## Response

The result is an XML document inside `GetExpensesRawResult`: a `tlp:Expenses` root with one `tlp:Expense` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: Purchase date DESCENDING; ties in no defined order.

<ResponseField name="tlp:Expense" field-type="Expense[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.
