| | |
|---|---|
| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetCustomerCommentsRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

'All' is 0 for every ID filter, including status. The date window applies to the note's own, user-entered date - not its creation time. Notes include automatic copies of e-mails sent from the CRM: FREE TEXT that may hold personal data of anyone.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="customerID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="customerStatusID" field-type="integer" required="true">
Customer status ID. 0 = no filter; applied when > 0.
</ResponseField>

<ResponseField name="accountManagerID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="fromDate" field-type="dateTime" required="true">
Note date >= value. An invalid value -> ASMX fault.
</ResponseField>

<ResponseField name="toDate" field-type="dateTime" required="true">
Note date &lt;= value, compared as datetime: a date without time excludes notes stamped later that day.
</ResponseField>

## Response

The result is an XML document inside `GetCustomerCommentsRawResult`: a `tlp:Comments` root with one `tlp:Comment` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: Customer name, then note ID DESCENDING.

<ResponseField name="tlp:Comment" field-type="Comment[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="Comment fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Note ID.**
</ResponseField>

<ResponseField name="CustomerName" field-type="string">
**Customer name.** Customer company name.
</ResponseField>

<ResponseField name="CustomerID" field-type="integer">
**Customer ID.** The note's customer.
</ResponseField>

<ResponseField name="CommentText" field-type="string">
**Text.** Note text. Free text; copies of sent e-mails hold recipient, subject and body.
</ResponseField>

<ResponseField name="Date" field-type="string">
**Note date.** The fromDate / toDate filter applies here.
</ResponseField>

<ResponseField name="Employee" field-type="integer">
**Employee ID.** Employee ID chosen on the note. Integer ID, not a name.
</ResponseField>

</Expandable>
</ResponseField>
