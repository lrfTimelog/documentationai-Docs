Returns each employee's expected working hours per day from the employee projection.

| | |
|---|---|
| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetWorkingHoursRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

Filters: employee, department, status, and a date range given as STRINGS. Without a date range the extract returns every projected day of every employee - potentially very large. status 0 does NOT return inactive employees.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="employeeID" field-type="integer" required="true">
Employee id; mapped to the employee's user first - an employee without a user returns nothing. 0 = no filter.
</ResponseField>

<ResponseField name="departmentID" field-type="integer" required="true">
Current profile department, exact. 0 = no filter.
</ResponseField>

<ResponseField name="status" field-type="integer" required="true">
Only values > 0 are sent: 1 = active employees only; 0 and negatives = ALL employees - 0 does NOT mean inactive, contrary to the XML comment.
</ResponseField>

<ResponseField name="startDate" field-type="string" required="true">
Send an empty value for no filter. Date >= value. Empty or UNPARSEABLE -> silently no limit. Use yyyy-MM-dd.
</ResponseField>

<ResponseField name="endDate" field-type="string" required="true">
Send an empty value for no filter. Date &lt;= value. Empty or UNPARSEABLE -> silently no limit. Use yyyy-MM-dd.
</ResponseField>

## Response

The result is an XML document inside `GetWorkingHoursRawResult`: a `tlp:WorkingHours` root with one `tlp:WorkingHour` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: Employee USER id only - the order of dates within an employee is NOT guaranteed.

<ResponseField name="tlp:WorkingHour" field-type="WorkingHour[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.
