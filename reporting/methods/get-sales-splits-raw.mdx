| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetSalesSplitsRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

The ID attribute identifies the SPLIT and repeats for each salesperson. Unlike GetProjectsRaw, splits of project templates are included. This is commission-related data per employee for the whole account.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="projectID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="status" field-type="integer" required="true">
Use `-2` for no filter. PROJECT active status; sent when > -2. The XML comment documents no parameter of this method.
</ResponseField>

<ResponseField name="customerID" field-type="integer" required="true">
Project's customer. 0 = no filter.
</ResponseField>

<ResponseField name="projectManagerID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

## Response

The result is an XML document inside `GetSalesSplitsRawResult`: a `tlp:SalesSplits` root with one `tlp:SalesSplit` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

<ResponseField name="tlp:SalesSplit" field-type="SalesSplitRaw[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="SalesSplit fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Sales split ID.**
</ResponseField>

<ResponseField name="ProjectID" field-type="integer">
**Project ID.** Project of the split.
</ResponseField>

<ResponseField name="EmployeeID" field-type="integer">
**Employee ID.** The salesperson.
</ResponseField>

<ResponseField name="SplitType" field-type="string">
**Split type.**
</ResponseField>

<ResponseField name="SplitPercentage" field-type="decimal">
**Split percentage.** SENSITIVE.
</ResponseField>

<ResponseField name="SplitAmount" field-type="decimal">
**Split amount.** SENSITIVE: commission per employee.
</ResponseField>

<ResponseField name="EmployeeLegalEntityID" field-type="integer">
**Employee legal entity.** Legal entity of the salesperson.
</ResponseField>

<ResponseField name="SystemCurrencySplitAmount" field-type="decimal">
**Split amount (system currency).** SplitAmount x the intercompany exchange rate from the PROJECT currency to the system currency valid at the project START date / 100. Omitted when no rate exists. Four decimals. SENSITIVE.
</ResponseField>

</Expandable>
</ResponseField>
