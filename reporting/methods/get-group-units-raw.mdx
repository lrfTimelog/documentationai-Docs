| | |
|---|---|
| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetGroupUnitsRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

Project assignments are returned without their project id. No ORDER BY. Free-text values may hold personal data about contacts.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="groupID" field-type="integer" required="true">
0 = no filter. The only filter that behaves as documented.
</ResponseField>

<ResponseField name="customerID" field-type="integer" required="true">
Use `0` for no filter. BROKEN: on its own it is ignored. With all three entity ids > 0, matches units whose customer, contact OR opportunity id equals customerID. Pass 0.
</ResponseField>

<ResponseField name="contactID" field-type="integer" required="true">
Use `0` for no filter. BROKEN: the value sent is customerID's, never contactID's. Pass 0.
</ResponseField>

<ResponseField name="opportunityID" field-type="integer" required="true">
Use `0` for no filter. BROKEN: the value sent is customerID's. Pass 0.
</ResponseField>

## Response

The result is an XML document inside `GetGroupUnitsRawResult`: a `tlp:GroupUnits` root with one `tlp:GroupUnit` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: None - no ORDER BY.

<ResponseField name="tlp:GroupUnit" field-type="GroupUnitsRaw[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="GroupUnit fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Group unit ID.**
</ResponseField>

<ResponseField name="CustomerID" field-type="integer">
**Customer ID.**
</ResponseField>

<ResponseField name="ContactID" field-type="integer">
**Contact ID.**
</ResponseField>

<ResponseField name="OpportunityID" field-type="integer">
**Opportunity ID.**
</ResponseField>

<ResponseField name="GroupID" field-type="integer">
**Group ID.**
</ResponseField>

<ResponseField name="ValueID" field-type="integer">
**Value ID.**
</ResponseField>

<ResponseField name="Value" field-type="string">
**Value.** ISNULL. Free text may describe a person - treat as personal data.
</ResponseField>

</Expandable>
</ResponseField>
