Returns CRM opportunities with customer, contact, owner, type, barriers, status, potential value, quotation and currency.

| | |
|---|---|
| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetOpportunitiesRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

Filters: opportunity, customer, owner, opportunity type, barrier and a date window. The date window uses the QUOTATION date and falls back to the creation date when no quotation date is set. Dates are STRINGS: an unparseable value is silently ignored. BarrierID is a ';'-delimited list, not one ID; the barrierID filter can miss opportunities. Opportunities whose customer no longer exists are dropped.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

<ResponseField name="opportunityID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="customerID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="ownerID" field-type="integer" required="true">
Employee in charge of the opportunity. 0 = no filter.
</ResponseField>

<ResponseField name="opportunityTypeID" field-type="integer" required="true">
0 = no filter.
</ResponseField>

<ResponseField name="barrierID" field-type="integer" required="true">
Barrier ID; matches opportunities whose barrier list contains ';&lt;id>;'. 0 = no filter. Can MISS opportunities whose list was saved with a space after ';'.
</ResponseField>

<ResponseField name="startDate" field-type="string">
**Optional.** Send yyyy-MM-dd.
</ResponseField>

<ResponseField name="endDate" field-type="string">
**Optional.** Same date, &lt;= value.
</ResponseField>

## Response

The result is an XML document inside `GetOpportunitiesRawResult`: a `tlp:Opportunities` root with one `tlp:Opportunity` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

<ResponseField name="tlp:Opportunity" field-type="OpportunitiesRaw[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="Opportunity fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Opportunity ID.**
</ResponseField>

<ResponseField name="CustomerID" field-type="integer">
**Customer ID.**
</ResponseField>

<ResponseField name="CustomerName" field-type="string">
**Customer name.** Customer company name.
</ResponseField>

<ResponseField name="ContactID" field-type="integer">
**Contact ID.** Customer contact; omitted when none.
</ResponseField>

<ResponseField name="ContactName" field-type="string">

</ResponseField>

<ResponseField name="OpportunityTypeID" field-type="integer">

</ResponseField>

<ResponseField name="OpportunityTypeName" field-type="string">
**Opportunity type.** Type name.
</ResponseField>

<ResponseField name="EmployeeName" field-type="string">
**Owner name.** First + last name.
</ResponseField>

<ResponseField name="BarrierID" field-type="string">
