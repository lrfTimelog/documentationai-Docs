| | |
|---|---|
| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetSalaryAccountsRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

No filters. Every absence code posts to a salary account, so account names can name an illness balance. Low sensitivity itself.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="siteCode" field-type="string" required="true">
Your account's site code, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiID" field-type="string" required="true">
The Reporting API ID, from the Reporting API settings.
</ResponseField>

<ResponseField name="apiPassword" field-type="string" required="true">
The Reporting API password, from the Reporting API settings.
</ResponseField>

```python
import requests

URL = "https://app{server-number}.timelog.com/{account}/Service.asmx"
SOAP_ACTION = '"http://www.timelog.com/ws/tlp/v4_4/GetSalaryAccountsRaw"'

envelope = """<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
               xmlns:tlp="http://www.timelog.com/ws/tlp/v4_4">
  <soap:Body>
    <tlp:GetSalaryAccountsRaw>
      <tlp:siteCode>{siteCode}</tlp:siteCode>
      <tlp:apiID>{apiID}</tlp:apiID>
      <tlp:apiPassword>{apiPassword}</tlp:apiPassword>
    </tlp:GetSalaryAccountsRaw>
  </soap:Body>
</soap:Envelope>"""

response = requests.post(
    URL,
    data=envelope.encode("utf-8"),
    headers={"Content-Type": "text/xml; charset=utf-8", "SOAPAction": SOAP_ACTION},
    timeout=300,
)
rows = parse_result(response)  # see "Responses and errors"
```

## Response

The result is an XML document inside `GetSalaryAccountsRawResult`: a `tlp:SalaryAccounts` root with one `tlp:SalaryAccount` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

Order: None.

<ResponseField name="tlp:SalaryAccount" field-type="SalaryAccountRaw[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="SalaryAccount fields">

<ResponseField name="ID" field-type="integer (attribute)">
**Salary account ID.**
</ResponseField>

<ResponseField name="GUID" field-type="string (attribute)">
**Salary account GUID.**
</ResponseField>

<ResponseField name="Name" field-type="string">
**Name.** NOT NULL.
</ResponseField>

<ResponseField name="Description" field-type="string">
**Description.** Nullable free text.
</ResponseField>

<ResponseField name="IsActive" field-type="integer">
**Active.** bit. Inactive and system accounts are included.
</ResponseField>

<ResponseField name="AccountType" field-type="string">
**Account type.**
</ResponseField>

<ResponseField name="BalanceFormat" field-type="string">
**Balance format.** BalanceFormat mapped to text; any other value -> omitted. Says which of Hours / Days / count the postings' balance is kept in.
</ResponseField>

<ResponseField name="Code" field-type="string">
**Code.** Account code.
</ResponseField>

</Expandable>
</ResponseField>
