| API | Reporting API (raw extracts) |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/Service.asmx` |
| SOAPAction | `http://www.timelog.com/ws/tlp/v4_4/GetHardBookingsRaw` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | `siteCode`, `apiID` and `apiPassword` as the first three parameters. See [Authentication](/reporting/guides/authentication) |
| Changes data | No. Safe to retry. |
| Paging | No: the whole result comes in one response. Narrow it with the filters. |

## How it works

Filters: the employee's USER id, a mandatory date range on the booked day, and the booking type. CAUTION: hardbookingType = 0 does NOT filter - it returns every type. There is no way to request manual bookings only; filter HardBookingType = 0 on the client. Planning data of every employee.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="apiID" field-type="string" required="true">

</ResponseField>

<ResponseField name="employeeUserId" field-type="integer" required="true">
USER id of the employee - not the employee id. 0 = no filter.
</ResponseField>

<ResponseField name="startDate" field-type="dateTime" required="true">
 
</ResponseField>

Booked day &lt;= value.
</ResponseField>

<ResponseField name="hardbookingType" field-type="integer" required="true">
Use `0` for no filter.
</ResponseField>

## Response

The result is an XML document inside `GetHardBookingsRawResult`: a `tlp:Hardbookings` root with one `tlp:Hardbooking` element per record. Check the [response format](/reporting/guides/responses-and-errors) first: the same slot also carries the empty result and errors.

<ResponseField name="tlp:Hardbooking" field-type="Hardbooking[]">
One element per record. Fields without a value are left out of the element, so treat every field as optional.

<Expandable title="Hardbooking fields">

<ResponseField name="GUID" field-type="string (attribute)">
**Booking detail GUID.**
</ResponseField>

<ResponseField name="ID" field-type="integer (attribute)">
**Booking detail ID.**
</ResponseField>

<ResponseField name="UserID" field-type="integer">
**User ID.**
</ResponseField>

<ResponseField name="AllocationID" field-type="integer">
**Allocation ID.** Allocation the booking draws on.
</ResponseField>

<ResponseField name="TaskID" field-type="integer">
**Task ID.** Task of that allocation.

<ResponseField name="TaskName" field-type="string">
