## How it works

The account's salary codes: the codes that time is posted under on the salary accounts - the system codes for normal working time and project time and the account's supplement / paid-out codes - with code, name, salary account, posting factor and sign, time-tracking format and specification type. The salaryCodeStatus parameter is IGNORED on every call returns active AND inactive codes - filter on IsActive yourself. Configuration only: factors are multipliers, not money; no employee data.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="salaryCodeStatus" field-type="string" required="true">
Meant to select active, inactive or all codes. IGNORED on V1_1 - every value returns all codes. Send 'All' so the request says what the response does. Allowed values: `All`, `Active`, `Inactive`.

</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back unchanged.

</ResponseField>

## Response

The call returns the standard [response envelope](/transactional/guides/responses-and-errors). **Check `ResponseState` first**: a failed call still returns HTTP 200.

<ResponseField name="ResponseState" field-type="string" required="true">
`Success`, `Invalid` or `Error`.
</ResponseField>

<ResponseField name="ErrorCode" field-type="integer">
`0` on success, otherwise the error code. See [Errors](#errors).
</ResponseField>

<ResponseField name="Return" field-type="Salary[]">
Response&lt;Salary>: every salary code, unpaged. No 'Successfully called' message is added; ResponseState Success. ResponseState Success with an empty Return when the account has no salary codes.

<Expandable title="Salary fields">

<ResponseField name="Code" field-type="string">

</ResponseField>

<ResponseField name="Name" field-type="string">

Which system category the code belongs to. The contract's XML comment lists other values - the enum below is what is serialised. Allowed values: `NormalWorkingTime`, `ProjectTime`.
</ResponseField>

<ResponseField name="SalaryAccountFactor" field-type="double">
Multiplier of the posting to the salary account. A factor, not an amount. The contract's XML comment calls it an Adds / Substracts enum.
</ResponseField>

<ResponseField name="FlexPositiveFactor" field-type="double">
 
</ResponseField>

Sign of the posting to the salary account. The contract's XML comment calls it a bool 'flex included'. Allowed values: `Substract`, `Add`.
</ResponseField>

Whether the code is active. GetAllSalaryCodes returns inactive codes too - filter on this.
</ResponseField>

<ResponseField name="SalaryCodeID" field-type="integer">
Integer identifier.
</ResponseField>

<ResponseField name="IsSystemSalaryCode" field-type="boolean">
Whether the code is a system salary code.

</ResponseField>

<ResponseField name="SalaryAccountID" field-type="integer">

</ResponseField>

<ResponseField name="TimeTrackingFormat" field-type="string">
How time on the code is entered. Allowed values: `Hours`, `FullDay`, `HalfDay`, `YesNo`, `Count`.
</ResponseField>

<ResponseField name="SalarySpecificationType" field-type="string">
Specification type of the code. Allowed values: `SalaryTime`, `Supplement`, `PaidOut`.
</ResponseField>
