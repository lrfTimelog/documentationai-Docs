Marks an allocation completed or not completed.

| | |
|---|---|
| Service | Project management 1.8 |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/WebServices/ProjectManagement/V1_8/ProjectManagementServiceSecure.svc` |
| SOAPAction | `SetAllocationStatusRequest` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | A token from [GetToken](/transactional/guides/authentication) |
| Changes data | Yes |
| Safe to retry | Yes |

## How it works

A completed allocation is inactive: the time-registration rules then refuse new time and changes on it for that employee. The allocation's ETC completion status is updated and an audit-log + e-mail event is raised. Setting the status it already has still saves and raises the event.

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'Object reference not set to an instance of an object.' | allocationGuid unknown or all zeros. | Re-read the allocation and send its ID. |
