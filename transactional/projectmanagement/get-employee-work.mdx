## How it works

Looks up the employee by initials, checks the caller may see that employee's time, and returns every PROJECT-time registration whose work date is >= startDate and &lt;= endDate. Each item is a WorkUnit with GUID, task ID, allocation GUID, duration, billable duration, comment, additional text, an IsEditable flag and Details. Dates: compared with the registration's date, so an endDate at 00:00 includes that day, but a startDate with a time of day after 00:00 EXCLUDES its own day. WorkUnit.StartDateTime comes back as the work date at 00:00 and EndDateTime as date + duration - not the stored start / end times. The list is not ordered and not paged.

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="initials" field-type="string" required="true">

</ResponseField>

<ResponseField name="startDate" field-type="dateTime" required="true">

</ResponseField>

<ResponseField name="endDate" field-type="dateTime" required="true">
Last work date.

</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back unchanged.

</ResponseField>

<Expandable title="WorkUnit fields">

<ResponseField name="GUID" field-type="guid">
 
</ResponseField>

<ResponseField name="AllocationGUID" field-type="guid">
GUID of the allocation the registration is booked on. Output only.
</ResponseField>

<ResponseField name="TaskID" field-type="integer">
Integer ID of the task the time is registered on. The allocation of this employee on the task is looked up, or CREATED when missing.
</ResponseField>

<ResponseField name="EmployeeInitials" field-type="string">
Initials of the employee who owns the registration. On write, decides the owner and department of the registration.
</ResponseField>

<ResponseField name="Duration" field-type="duration">
PT1H30M). Stored as decimal hours.
</ResponseField>

<ResponseField name="StartDateTime" field-type="dateTime">
Only the DATE part is used: it is the registration's work date. The time of day is ignored on write; on read it is always 00:00.
</ResponseField>

<ResponseField name="EndDateTime" field-type="dateTime">
Ignored on write. On read = the registration date plus the duration - a computed value, not a stored end time.
</ResponseField>

<ResponseField name="Description" field-type="string">
The registration's comment.
</ResponseField>

<ResponseField name="TimeStamp" field-type="base64Binary">
Never filled on read and ignored on write - there is no optimistic concurrency check; the last write wins.
</ResponseField>

<ResponseField name="IsEditable" field-type="boolean">
False in every batch response.
</ResponseField>

<ResponseField name="AdditionalText" field-type="string">
The registration's additional text field.
</ResponseField>

<ResponseField name="IsMeeting" field-type="boolean">
Never filled on read and ignored on write.
</ResponseField>

<ResponseField name="BillableDuration" field-type="duration">
The billable part of the duration, stored as decimal billable hours; kept only when the registration is billable.
</ResponseField>

<ResponseField name="Details" field-type="WorkUnitDetails">
Headers of the task, its project and the project's customer. Output only; null when the task cannot be loaded.
</ResponseField>

</Expandable>

</ResponseField>
