## How it works

Creates the allocation of Allocation.EmployeeID on Allocation.TaskID. Unlike AddEmployeeToTask, the caller can set the allocation's GUID, the contract hourly rate, the start / end dates and external keys. The employee is added to the project's resource group when missing and the project is saved. Rules checked: employee exists, the employee is not already on the task, the task exists, is not a parent task and is not completed / cancelled. NOT checked: whether HourlyRateID belongs to the task's project contract or is an indexed rate, and whether the caller may staff the project.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 30008 | Server unable to create allocation, Task and Employee relationship already exists on allocation:  | The employee is already allocated to the task. | Treat as 'already allocated': read the allocation and update it instead. |
| Error | 30009 | Unable to validate allocation for creation: Allocation is associated with parent task. | TaskID has sub-tasks. | Allocate the employee to a sub-task. |
| Error | 37808 | Allocation cannot be added to cancelled or completed task. | The task is completed or cancelled. | Reopen the task or choose another task. |
