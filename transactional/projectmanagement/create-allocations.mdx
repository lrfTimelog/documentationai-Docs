Creates several allocations in one call - but reports every created allocation as a duplicate.

| | |
|---|---|
| Service | Project management 1.8 |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/WebServices/ProjectManagement/V1_8/ProjectManagementServiceSecure.svc` |
| SOAPAction | `CreateAllocationsRequest` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | A token from [GetToken](/transactional/guides/authentication) |
| Changes data | Yes |
| Safe to retry | No |

## How it works

For each Allocation in the list, in order: the task is loaded, the request values are mapped and the allocation is CREATED through the same path as CreateAllocation. So an all-Invalid response is the NORMAL successful outcome. External keys sent on the items are ignored.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 30008 | Server unable to create allocation, Task and Employee relationship already exists on allocation:  | First pass: an item's employee is already on its task - the call aborts, earlier items stay created. | Treat as 'already allocated': read the allocation and update it instead. |
| Error | 30009 | Unable to validate allocation for creation: Allocation is associated with parent task. | First pass: parent task - call aborts. | Allocate the employee to a sub-task. |
| Error | 37808 | Allocation cannot be added to cancelled or completed task. | First pass: completed / cancelled task - call aborts. | Reopen the task or choose another task. |
| Error | — | — | Large batch inserts are the realistic trigger. | Split the batch into smaller requests. |
