## How it works

The status decides whether time can be registered: In progress opens the project, On hold / Completed / Archived / Cancelled close it, Quote / Approved keep the project's current setting. Closing also completes - or for Cancelled cancels - every open contract of the project and completes all its milestones; re-opening does NOT reopen them. No check is made for unapproved or unbilled time when closing, nor for invoices when re-opening; the only rule is that a project with a multi-customer contract still on the system customer cannot be completed. The returned read model does not contain the status - you cannot read it back through this service.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 37969 | Error during call on TimeLog.API, Message 'The change order status for Project has been violated.'  (rule text: 'There is a contract that has not been assigned a customer') | targetStatus 4 on a project with an MCP contract still on the system customer. | Assign a customer to every contract, then complete the project. |
