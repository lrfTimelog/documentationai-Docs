Returns the allocation mapped to an external ID in a named external system.

| | |
|---|---|
| Service | Project management 1.8 |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/WebServices/ProjectManagement/V1_8/ProjectManagementServiceSecure.svc` |
| SOAPAction | `GetAllocationByExternalKeyRequest` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | A token from [GetToken](/transactional/guides/authentication) |
| Changes data | No |
| Safe to retry | Yes |

## How it works

Resolves through the external-system mappings of allocations and returns that allocation. The response is flagged as paged although it holds at most one item. An unknown system name does not produce the 'unknown external system' error: the look-up returns an empty GUID and the call fails with a null-reference text.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'The external key "\{externalID\}" was not found for the chosen external system "\{systemName\}".' | The system exists but no allocation is mapped to `key`. | Create the contact first; a not-found is a normal outcome for sync look-ups. |
| Error | 40001 | Error during call on TimeLog.API, Message 'Object reference not set to an instance of an object.' | `systemName` is not a registered external system, or the mapping points at an allocation that no longer exists. | Re-read the allocation and send its ID. |
