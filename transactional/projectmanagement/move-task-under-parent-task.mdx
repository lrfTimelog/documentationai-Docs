## How it works

Loads the task by Task.ID. When parentTaskID differs from the task's current parent, the task is moved inside its own project: under the task with integer TaskID parentTaskID, or to the end of the root level when parentTaskID is 0. With changeToParentContract = true the moved task and its sub-tasks are first moved to the receiver's contract through the same guarded path as ChangeTaskContract. The old parent's payment is rebuilt when it lost a child, and the project is saved. Registrations stay on the task, so they never change project or customer.
