## How it works

Loads the project by integer ID, builds a new task with the project's default task status, billable flag and invoicing type, appends it as the next root WBS number, maps the members of the Task you send, puts it on ProjectSubContractID, applies HourlyRateID and saves the project. Use CreateSubTask to create a task under another task.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message '\{rule text\}' - one message per violated rule, then 'Task is not in an invalid state to be saved' | Name empty, start / end date missing or end before start. | Send Name, StartDate and EndDate; create sub-tasks only under tasks without allocations. |
| Error | 40001 | Error during call on TimeLog.API, Message 'The specified contract ID does not exist in the project.' | ProjectSubContractID is not a contract of the project. | Send 0 or a contract of the project. |
| Error | 40001 | Error during call on TimeLog.API, Message 'The specified HourlyRateID \{HourlyRateID\} do not exist, is in-active or not in the Price List of the Project related to the specified ProjectID: \{ProjectID\}' | HourlyRateID not valid for the project. | Send 0, or a rate valid for the project's price list. |
| Error | 40001 | Error during call on TimeLog.API, Message 'TypeID has to be > 0 on Task. Current value: \{TaskTypeID\}' | account requires task types. | Send a TaskTypeID. |
