| Paging | Yes, up to 500 per page |

## How it works

Lists the contact persons of the customer identified by customerId. Only ACTIVE contacts are returned. The full list is loaded and then sliced in memory: page is 1-based, pageSize is capped at 500, and TotalPageCount in the envelope tells how many pages exist. Set loadCustomFields / loadExternalKeys to fill each contact's custom fields and external keys.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="customerId" field-type="guid" required="true">
GUID of the customer.

</ResponseField>

<ResponseField name="loadCustomFields" field-type="boolean">
**Optional.** Default `false`. true = fill each contact's CustomFields.

</ResponseField>

<ResponseField name="loadExternalKeys" field-type="boolean">
**Optional.** Default `false`. true = fill each contact's ExternalKeys.

</ResponseField>

<ResponseField name="page" field-type="integer" required="true">
1-based page number. Values &lt;= 0 behave like 1.

</ResponseField>

<ResponseField name="pageSize" field-type="integer" required="true">
Contacts per page; values above 500 are lowered to 500. Must be > 0.

</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back unchanged.

</ResponseField>
