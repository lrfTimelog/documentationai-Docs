---
title: "GetCustomersModifiedSincePaged"
description: "CRM service 1.4: the customer sync feed. Customers created, changed or deleted since a date, or all customers, a page at a time."
---

Returns the customers that were **created, changed or deleted since a date**, or **all customers**, filtered by
customer group, one page at a time. Use it to keep another system's customer list in sync with TimeLog.

| | |
|---|---|
| Service | CRM 1.4 |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/WebServices/CRM/V1_4/CRMServiceSecure.svc` |
| SOAPAction | `http://api.timelog.com/services/crm/1_4/ICRMService/GetCustomersModifiedSincePaged` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | A token from [GetToken](/transactional/guides/authentication) |
| Permissions | The token's user needs access to customers |
| Changes data | No. Safe to retry. |
| Paging | Yes, up to 500 customers per page |

## Two modes

The `date` you send decides what you get back:

| `date` | Mode | Returns | `Action` on each customer |
|---|---|---|---|
| On or after 2000-01-01 | **Changes** | One entry per customer created, changed or deleted at or after `date` | `Created`, `Updated` or `Deleted` |
| Before 2000-01-01 (e.g. `1900-01-01T00:00:00`) | **Full list** | Every customer in the selected groups | Always `Created` |

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="date" field-type="dateTime" required="true">
Return changes made at or after this moment, in the TimeLog server's local time.
Format `YYYY-MM-DDThh:mm:ss`, e.g. `2026-10-01T00:00:00`. A date before 2000-01-01 switches to the full list.
</ResponseField>

<ResponseField name="includeCustomers" field-type="boolean">
**Conditional.** `true` to include customers whose status is in the *Customers* group.
At least one of `includeCustomers`, `includeSuppliers` and `includeLeads` must be `true`: with all three `false`
the result is always empty.
</ResponseField>

<ResponseField name="includeSuppliers" field-type="boolean">
**Conditional.** `true` to include suppliers. See `includeCustomers`.
</ResponseField>

<ResponseField name="includeLeads" field-type="boolean">
**Conditional.** `true` to include leads. See `includeCustomers`.
</ResponseField>

<ResponseField name="loadCustomFields" field-type="boolean">
**Optional.** Default `false`. `true` fills `CustomFields` on each returned customer. Adds work per customer: leave it
off unless you need the values.
</ResponseField>

<ResponseField name="loadExternalKeys" field-type="boolean">
**Optional.** Default `false`. `true` fills `ExternalKeys` (the customer's IDs in other systems) on each returned
customer.
</ResponseField>

<ResponseField name="page" field-type="integer" required="true">
The page to return, starting at `1`.
</ResponseField>

<ResponseField name="pageSize" field-type="integer" required="true">
Customers per page: `1` to `500`. Larger values are lowered to 500.
</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back
unchanged.
</ResponseField>

## Response

The call returns the standard [response envelope](/transactional/guides/responses-and-errors). **Check
`ResponseState` first**: a failed call still returns HTTP 200.

<ResponseField name="ResponseState" field-type="string" required="true">
`Success`, `Invalid` or `Error`.
</ResponseField>

<ResponseField name="ErrorCode" field-type="integer">
`0` on success, otherwise the error code. See [Errors](#errors).
</ResponseField>

<ResponseField name="TotalPageCount" field-type="integer">
Number of pages for the whole result with your `pageSize`. Keep calling with `page` + 1 until you have read them all.
</ResponseField>

<ResponseField name="Return" field-type="Customer[]">
The customers on this page. Empty (with `ResponseState` = `Success` and `TotalPageCount` = `0`) when nothing matched.

The customer's stable ID. Use it to match customers between your system and TimeLog.
</ResponseField>

</ResponseField>

<ResponseField name="Name" field-type="string">

</ResponseField>

<ResponseField name="No" field-type="string">

Status, industry, currency and account managers as objects with their IDs.
</ResponseField>

<ResponseField name="CustomFields" field-type="CustomField[]">

<ResponseField name="ExternalKeys" field-type="ExternalSystemContext[]">
The customer's IDs in other systems. Filled only when `loadExternalKeys` is `true`.
</ResponseField>

</Expandable>
</ResponseField>

`Deleted`. In **full-list** mode, `KAM`, `Contacts` and the account managers in `Details` are left empty: read the
customer by GUID if you need them.</Callout>

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation
can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in
[Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'User does not have the right to access any customers' | The token's user has no access to customers. | Give the integration user access to customers. |

## Keeping customers in sync

<Steps>
<Step title="Initial load" icon="download">
Call once with `date` = `1900-01-01T00:00:00` and read every page. Store each customer by `GUID`. If you need account
managers or contacts, read those customers by GUID afterwards: the full list leaves them empty.
</Step>
<Step title="Remember when you ran" icon="clock">
Before each run, note the current time in the TimeLog server's time zone. That is the `date` for the next run.
</Step>
<Step title="Apply the changes" icon="refresh-cw">
Call with the `date` of the previous run and read every page. Apply `Created` and `Updated`, and remove `Deleted`
customers from your copy.
</Step>
</Steps>

<Callout kind="tip">Let runs overlap a little rather than leave gaps: changes at exactly `date` are included, and a
customer seen twice is simply applied twice. Read all pages of one run quickly: new changes arriving between pages can
shift the page contents.</Callout>

<Callout kind="info">`Deleted` means the customer is no longer in the result you asked for: deleted in TimeLog, or
moved to a status outside the groups you selected. Treat it as "remove from my copy".</Callout>
