## How it works

Builds a new user from the parameters, resolving working time, holiday calendar, allowance legislation, employee type, cost price and hourly rate BY NAME and the department by GUID, and saves it. Fixed by the server: licence Standard, the system salary group, the default legal entity, server time zone, language English, employment date = now. The employee is created INACTIVE - call ActivateEmployee. No password is set and no e-mail is sent: the employee sets a password through the link CreateEmployeeNotification e-mails. User name and initials must not clash with ANY existing user, active or inactive. The response is the unsaved object: EmployeeID is 0.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'The \{normal working week \| holiday calendar \| allowance settings \| employee type \| cost price \| hourly rate\} was not found' / 'The department is not found' | A working time, holiday calendar, allowance, employee type, cost price, hourly rate or department look-up failed. | — |
| Error | 40001 | Error during call on TimeLog.API, Message '\{The email address is mandatory \| No first name was provided \| No last name was provided \| No initials was provided \| No user name was provided\}' | email, firstname, lastname or initials blank. | Send the value. |
| Error | 40001 | Error during call on TimeLog.API, Message 'The title exceeds the maximum length of 50 characters' | V1_9 only: title longer than 50 characters. | Shorten the title to 50 characters. |
| Error | 40001 | Error during call on TimeLog.API, Message 'The user violates the Business Rules for users' | Save refused: missing employee create privilege, user name / initials already used, invalid e-mail or employee number, invalid references. | Check the integration user's employee privileges first; then uniqueness of initials / user name; then the referenced data. |
| Error | — | — | — | Always send the string parameter, even as an empty string. |
