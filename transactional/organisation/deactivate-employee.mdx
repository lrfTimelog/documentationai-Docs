| Content-Type | `text/xml; charset=utf-8` |
| Authentication | A token from [GetToken](/transactional/guides/authentication) |
| Changes data | Yes |
| Safe to retry | Deactivating an already inactive employee saves the date again and repeats the status-change notifications. |

## How it works

Two steps, not atomic. The caller may deactivate themselves. Existing SOAP tokens of the deactivated user keep working until they expire. Reactivate with ActivateEmployee.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="employeeGuid" field-type="guid" required="true">
GUID of the employee.

</ResponseField>

<ResponseField name="terminationDate" field-type="dateTime" required="true">
Stored as the resignation date. Must be >= the employment date and >= the employee's last time registration. Does NOT delay the deactivation.

</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back unchanged.

</ResponseField>

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'Object reference not set to an instance of an object.' | employeeGuid unknown. | Take the GUID from EmployeeHeader.ID. Do not retry. |
| Error | 40001 | Error during call on TimeLog.API, Message 'The user violates the Business Rules for users' | Step 1 refused - typically no employee-edit privilege covering this employee, or terminationDate before the employment date. | Check the integration user's employee privileges first; then uniqueness of initials / user name; then the referenced data. |
| Error | 40001 | Error during call on TimeLog.API, Message 'The user violates the business roles for changing user status' | Step 2 refused: last system administrator, GDPR contact or last customer system owner. The resignation date is already saved. | Reassign the admin role / GDPR contact / system owner, then call again. Re-check the termination date. |
| Error | 40001 | Error during call on TimeLog.API, Message 'System.Collections.Generic.List`1[TimeLog.TLP.Error.IViolation]' | terminationDate earlier than the employee's last time registration: nothing is saved but the status-change notifications fire. | DeactivateEmployee: use a termination date on or after the last registration. |
| Error | — | — | Token missing / expired / invalid, API not activated or HTTPS required: the catch block fails on a null violations list. | Always send the string parameter, even as an empty string. |
