## How it works

Unlike GetRoles there is no filtering.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="employeeGuid" field-type="guid" required="true">

</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">

</ResponseField>

## Response

The call returns the standard [response envelope](/transactional/guides/responses-and-errors). **Check `ResponseState` first**: a failed call still returns HTTP 200.

<ResponseField name="ResponseState" field-type="string" required="true">
`Success`, `Invalid` or `Error`.
</ResponseField>

<ResponseField name="ErrorCode" field-type="integer">
`0` on success, otherwise the error code. See [Errors](#errors).
</ResponseField>

<ResponseField name="Return" field-type="Role[]">
Response&lt;Role>: Return = the employee's roles; a success message is added. Not expected for a real employee.

<Expandable title="Role fields">

<ResponseField name="ID" field-type="guid">
GUID of the role - the roleGuid that AddRoleToEmployeeByGuid / RemoveRoleFromEmployeeByGuid accept.
</ResponseField>

<ResponseField name="RoleID" field-type="integer">

</ResponseField>

<ResponseField name="Name" field-type="string">

</ResponseField>

<ResponseField name="Description" field-type="string">
Free-text description of the role.
</ResponseField>

<ResponseField name="isActive" field-type="boolean">
Whether the role is active. GetRoles returns active roles only; GetEmployeeRoles returns the employee's roles regardless.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'Object reference not set to an instance of an object.' | employeeGuid is not an employee of this account. | Take the GUID from EmployeeHeader.ID. Do not retry. |
