## How it works

<Callout kind="alert">**Full replace.** Every field you do not send is cleared (text emptied, numbers set to 0, booleans set to false). Read the record first, change what you need, and send it back complete.</Callout>

This is the only way to activate a department created with CreateDepartment, and the way to reactivate one deactivated with DeactivateDepartment. Other stored attributes are not touched. A changed name is also pushed to the Resource Planner service.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="departmentGuid" field-type="guid" required="true">
GUID of the department to update.

</ResponseField>

<ResponseField name="name" field-type="string" required="true">
New name. Null / empty -> 'Department is not in an invalid state to be saved'; whitespace-only is accepted.

</ResponseField>

<ResponseField name="no" field-type="string">
**Optional.** Default null -> the number is CLEARED. New department number. Not checked for uniqueness.

</ResponseField>

<ResponseField name="parentDepartmentGuid" field-type="guid">
**Optional.** GUID of the new parent - send the current ParentDepartmentGuid to keep it.

</ResponseField>

<ResponseField name="departmentManagerGuid" field-type="guid">
**Optional.**

</ResponseField>

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back unchanged.

</ResponseField>

## Response

The call returns the standard [response envelope](/transactional/guides/responses-and-errors). **Check `ResponseState` first**: a failed call still returns HTTP 200.

<ResponseField name="ResponseState" field-type="string" required="true">
`Success`, `Invalid` or `Error`.
</ResponseField>

<ResponseField name="ErrorCode" field-type="integer">
`0` on success, otherwise the error code. See [Errors](#errors).
</ResponseField>

<ResponseField name="Return" field-type="Department[]">
Response&lt;Department>: Return holds the saved department. Success message names return type 'Department'. Never - failure is an Error envelope with an empty Return.

<Expandable title="Department fields">

<ResponseField name="Action" field-type="string">
Allowed values: `Original`, `Created`, `Updated`, `Deleted`, `Copied`, `Undefined`.
</ResponseField>

<ResponseField name="IsCustomFieldsLoaded" field-type="boolean">
`true` when `CustomFields` is filled.
</ResponseField>

<ResponseField name="CustomFields" field-type="CustomField[]">
Custom field values.
</ResponseField>

<ResponseField name="IsExternalKeysLoaded" field-type="boolean">
`true` when `ExternalKeys` is filled.
</ResponseField>

<ResponseField name="ExternalKeys" field-type="ExternalSystemContext[]">
The record's IDs in other systems.
</ResponseField>

<ResponseField name="ID" field-type="guid">
GUID of the department. The value UpdateDepartment, DeactivateDepartment, ChangeEmployeeDepartment and the parentDepartmentGuid parameters take.
</ResponseField>

<ResponseField name="Name" field-type="string">
Department name. Not unique. GetDepartments sorts by it. Create rejects an empty or whitespace-only name; Update rejects only an empty one.
</ResponseField>

<ResponseField name="No" field-type="string">
Free-text department number - the key GetDepartmentByNo looks up. NOT unique: no constraint, and Create / Update do not check it; GetDepartmentByNo then fails for every duplicated number. A missing number is returned as an empty string.
</ResponseField>

<ResponseField name="ParentDepartmentGuid" field-type="guid">
The tree is at most four levels deep.
</ResponseField>

<ResponseField name="DepartmentManagerGuid" field-type="guid">
Only the GUID - no name or contact data. Once set, the API cannot clear it.
</ResponseField>

<ResponseField name="DepartmentID" field-type="integer">
Integer identifier of the department - the value Employee.DepartmentID and project department references carry. CreateDepartment returns 0 here - read it back with GetDepartmentByNo or GetDepartments.
</ResponseField>

</Expandable>

</ResponseField>

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'Your site doesn't have departments enabled' | The department reads are not gated. | Enable departments on the account, or do not maintain departments through the API. |
| Error | 40001 | Error during call on TimeLog.API, Message 'Unable to retrieve department from … with DepartmentGUID \{guid\}' | departmentGuid or parentDepartmentGuid does not exist. | Take the GUID from GetDepartments or GetDepartmentByNo. |
| Error | 40001 | Error during call on TimeLog.API, Message 'Department name is not allowed to be empty' | name null or empty - here with the domain-validation text 'Department is not in an invalid state to be saved'. | Send a non-empty name. |
| Error | 40001 | Error during call on TimeLog.API, Message 'No employee with ID "\{guid\}" found.' | departmentManagerGuid is not an employee GUID. | — |
| Error | 40001 | Error during call on TimeLog.API, Message 'The Department violates the Business Rules for Departments' | New parent on level 4, the moved sub-tree would exceed four levels, or the parent is the department itself / one of its descendants. | Choose a parent higher in the tree. |
