## How it works

The mail contains the site URL, the initials and a set-password link that lets the holder set a NEW password for the account for 15 days; it works whether or not the employee already has a password, so it is effectively a password reset. The link's token is derived from the employee's GUID, integer ID and the date, with no secret.

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in [Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'Employee doesn't have a valid email address (Email: \{email\})' | The stored e-mail has no '@'. | Correct the e-mail, then call again. |
| Error | 40001 | Error during call on TimeLog.API, Message 'Object reference not set to an instance of an object.' | employeeGuid unknown, or the stored e-mail is NULL. | Take the GUID from EmployeeHeader.ID. Do not retry. |
