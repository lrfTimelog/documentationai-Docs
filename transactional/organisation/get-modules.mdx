## How it works

Order: CRM, then Salary or Outlook, then Jira. An empty Return means none of these add-ons is active. The Name is what AddModuleToEmployee / RemoveModuleFromEmployee take.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="token" field-type="SecurityToken" required="true">
The token from [GetToken](/transactional/guides/authentication): `Initials`, `Expires` and `Hash`, sent back unchanged.

</ResponseField>

## Response

The call returns the standard [response envelope](/transactional/guides/responses-and-errors). **Check `ResponseState` first**: a failed call still returns HTTP 200.

<ResponseField name="ResponseState" field-type="string" required="true">
`Success`, `Invalid` or `Error`.
</ResponseField>

<ResponseField name="ErrorCode" field-type="integer">
`0` on success, otherwise the error code. See [Errors](#errors).
</ResponseField>

<ResponseField name="Return" field-type="ModuleType[]">
Response&lt;ModuleType>: Return = 0-3 modules. Return empty + success message when none of the add-ons is active on the account.

<Expandable title="ModuleType fields">

<ResponseField name="ID" field-type="integer">
Integer value of the module. GetModules returns only 1, 4, 9 or 15.
</ResponseField>

<ResponseField name="Name" field-type="string">
'CRM', 'Outlook', 'Jira', 'Salary'. This is the value AddModuleToEmployee expects.
</ResponseField>

</Expandable>
