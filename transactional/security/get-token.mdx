Exchanges the user name and password of a TimeLog user for a **token**. Every other Transactional API operation needs
that token. How to use it is explained in [Authentication](/transactional/guides/authentication).

| | |
|---|---|
| Service | Security 1.2 |
| Endpoint | `POST https://app{server-number}.timelog.com/{account}/WebServices/Security/V1_2/SecurityServiceSecure.svc` |
| SOAPAction | `GetTokenRequest` |
| Content-Type | `text/xml; charset=utf-8` |
| Authentication | None: this operation issues the token |
| Changes data | No |
| Safe to retry | Yes after a successful call. Do not retry a failed login automatically. |

## How it works

On success, `Return` holds one token with three values: `Initials`, `Expires` and `Hash`. Send them back unchanged as
the last parameter, `token`, of every other operation, on any service. The token is valid for **12 hours** and cannot
be refreshed: call GetToken again when it expires.

## Parameters

Each parameter has one label: **Required**, **Conditional** (required depending on other values) or **Optional**.
Send them in the order shown.

<ResponseField name="user" field-type="string" required="true">
The TimeLog **user name** of the user the integration runs as. Not the initials.
</ResponseField>

<ResponseField name="password" field-type="string" required="true">
That user's TimeLog password.
</ResponseField>

## Request

<Request uid="trx-security-gettoken-req" show-lines="true" tabs={["XML", "cURL", "Python"]}>

```xml
POST /{account}/WebServices/Security/V1_2/SecurityServiceSecure.svc HTTP/1.1
Host: app{server-number}.timelog.com
Content-Type: text/xml; charset=utf-8
SOAPAction: "GetTokenRequest"

<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:sec="http://www.timelog.com/api/tlp/v1_2">
  <soapenv:Body>
    <sec:GetToken>
      <sec:user>{user name}</sec:user>
      <sec:password>{password}</sec:password>
    </sec:GetToken>
  </soapenv:Body>
</soapenv:Envelope>
```

```bash
curl -X POST "https://app{server-number}.timelog.com/{account}/WebServices/Security/V1_2/SecurityServiceSecure.svc" \
  -H "Content-Type: text/xml; charset=utf-8" \
  -H 'SOAPAction: "GetTokenRequest"' \
  --data-binary @gettoken.xml
```

```python
import requests

URL = "https://app{server-number}.timelog.com/{account}/WebServices/Security/V1_2/SecurityServiceSecure.svc"

envelope = """<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:sec="http://www.timelog.com/api/tlp/v1_2">
  <soapenv:Body>
    <sec:GetToken>
      <sec:user>{user}</sec:user>
      <sec:password>{password}</sec:password>
    </sec:GetToken>
  </soapenv:Body>
</soapenv:Envelope>"""

response = requests.post(
    URL,
    data=envelope.format(user=USER_NAME, password=PASSWORD).encode("utf-8"),
    headers={"Content-Type": "text/xml; charset=utf-8", "SOAPAction": '"GetTokenRequest"'},
    timeout=30,
)
token = parse_result(response)[0]  # see "Responses and errors"
```

</Request>

<Callout kind="tip">Replace every `{…}` placeholder with your own value.</Callout>

## Response

The call returns the standard [response envelope](/transactional/guides/responses-and-errors). **Check
`ResponseState` first**: a failed call still returns HTTP 200.

<ResponseField name="ResponseState" field-type="string" required="true">
`Success`, `Invalid` or `Error`.
</ResponseField>

<ResponseField name="ErrorCode" field-type="integer">
`0` on success, otherwise the error code. See [Errors](#errors).
</ResponseField>

<ResponseField name="Return" field-type="SecurityToken[]">
One token on success; empty when the call failed.

<Expandable title="SecurityToken fields">

<ResponseField name="Initials" field-type="string">
The initials of the user the token belongs to.
</ResponseField>

<ResponseField name="Expires" field-type="dateTime">
When the token stops working, 12 hours after it was issued. Send it back exactly as received.
</ResponseField>

<ResponseField name="Hash" field-type="string">
The signature of the token.
</ResponseField>

</Expandable>
</ResponseField>

## Errors

All errors come back with **HTTP 200**: check `ResponseState`, `ErrorCode` and `Messages`. The errors every operation
can return (expired or invalid token, API not enabled, HTTPS required, general errors) are listed once in
[Responses and errors](/transactional/guides/responses-and-errors#error-codes).

Errors specific to this operation:

| ResponseState | ErrorCode | Message | What it means | What to do |
|---|---|---|---|---|
| Error | 40001 | Error during call on TimeLog.API, Message 'User or Password invalid or unknown, TLP can be case sensetive depending on settings' | The user could not be logged in. The same answer is given for every reason (unknown user, wrong password, inactive user). | Check the user name (not the initials) and the password. Do not retry automatically. |
